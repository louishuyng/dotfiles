# Improvement plans

Generated by `improve` on 2026-08-10, against commit `9c7d0ed5`.

**Audit scope:** `nvim/` (~110 Lua files, 5.4k LOC) and `terminals/fish/` (~108 files, 4.3k LOC),
plus the repo-root docs that describe them (`AGENTS.md`, `docs/key-bindings-nvim.md`,
`docs/git-shortcuts.md`).

**Not audited:** everything else in the repo — `suckless/`, `terminals/tmux/`, `terminals/ghostty/`,
`bootstrap/`, `home-manager/`, `devops/`, `scripts/`, `config/`, `.doom.d/`, `opencode/`.
`terminals/fish/fisherman/` (vendored third-party plugins) was excluded except for supply-chain
notes. No test-coverage findings: neither subtree has or wants a test suite.

**Verification baseline.** There is no build, no CI, and no test suite. The commands that stand in
for one:

```bash
nvim --headless +qa 2>&1          # config loads; see the trap below
stylua --check nvim/              # Lua formatting (12 files fail at 9c7d0ed5 — pre-existing)
fish --no-execute <file>.fish     # fish syntax
fish_indent -w <file>.fish        # fish formatting
```

Two traps every plan repeats, because they will bite an executor who does not know them:

1. **`nvim --headless +qa` exits 0 even when `init.lua` throws.** The error goes to stderr and the
   exit code stays 0. Assert on the *output text*, never the exit code.
2. **One line of stderr is pre-existing noise** at commit `9c7d0ed5`, emitted by a third-party
   plugin, not by this config:
   ```
   vim.tbl_flatten is deprecated. Run ":checkhealth vim.deprecated" for more information
   ```
   Treat a run as clean if it is empty or contains only that line. Do not chase it.

## What each plan covers

- **001** — `M.config.dark = 'tokyonight'` names a theme with no adapter. Reproduced: with an empty
  state dir, `require('config')` throws `E5113` and `mappings`/`cmds`/`ui`/`options` never load. A
  fresh clone gets an unusable editor. Masked today only by an existing `theme.json`.
- **002** — `shellescape()` output is re-wrapped in quotes, cancelling the escaping. `<leader>ou` on
  a crafted line in any file is arbitrary command execution. Replaced with `vim.ui.open()`.
- **003** — Three things that fail on a keypress: every `.txt` buffer forks `npx` at a path that does
  not exist; `LspAttach` reads the wrong buffer's name and silently drops LSP keymaps; `<CR>` is
  rebound in `.http` buffers to a command from an uninstalled plugin.
- **004** — `PlistBuddy` forks on every prompt render (measured 11.7 ms) to read a value that changes
  twice a day. Gated behind `builtin path mtime` (0.07 ms). Also measures, but does not change, the
  larger `mise hook-env` per-prompt cost — that one needs a user decision.
- **005** — `git rev-parse` runs at module load on every startup (~19 ms of a 241 ms total) for a
  Python-only feature, leaks stderr outside a repo, and pins `PYTHONPATH` to the launch directory.
  Plus: the 100 KB treesitter guard is on `BufReadPre` and so always runs before the `FileType`
  handler that starts treesitter — it has never fired.

## Direction suggestions (not plans)

Options for the maintainer, not defects.

- **Generate a tracked pack lockfile.** `vim.pack` already maintains a commit-pinned lockfile at
  `~/.config/nvim/nvim-pack-lock.json` — verified: it has a `rev` SHA per plugin. The gap is that it
  lives outside the repo and is not version-controlled, so a bad upstream commit still has no
  rollback path in git. `PackClean` in `nvim/lua/config/pack.lua:103-124` shows the `vim.pack.get()`
  extension point already exists. **S–M.**
- **One appearance signal instead of three.** `auto-dark-mode.nvim` (1000 ms poll), the fish
  PlistBuddy probe, and `defaults read` in `terminals/fish/functions/k7s.fish` each detect light/dark
  independently, and they have already diverged in *which* theme they pick — fish is hardwired to
  catppuccin while the Neovim state file holds `{"light":"github","dark":"catppuccin"}`. One listener
  on `AppleInterfaceThemeChangedNotification` writing a marker file would serve all three. Risk: if
  the listener dies the theme freezes with no obvious cause, so it needs a fallback. **M.**
- **A pre-push smoke check.** `nvim --headless +qa` runs in ~0.3 s and would have caught 001, which
  has been latent since commit `57254805`. Wrap it with `fish --no-execute` over the fish files and
  `stylua --check nvim/`. Pre-push rather than pre-commit, because `vim.pack` may hit the network on
  a cold cache. Caveat: it must assert on stderr with an allowlist for the known `vim.tbl_flatten`
  line, or it fails on day one and trains you to `--no-verify`. **S.**

## Note on audit side effects

Two audit agents ran Neovim to verify findings, which pulled `copilot.vim` and `opencode.nvim` (both
commented out in `pack.lua`) into `~/.local/share/nvim/site/pack/core/opt/`. Both were removed and
the plugin directory verified back at its expected 67 entries. `~/.config/nvim/nvim-pack-lock.json`
was also deleted during cleanup before it was understood to be vim.pack's own file — Neovim
regenerated it automatically on the next start ("Repaired corrupted lock data"), and a subsequent
start was clean. **No file in the repository was modified by the audit.**
