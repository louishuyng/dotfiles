# Neovim performance and health verification — 2026-10-12

The commit-editor stall is fixed, exercised features report no deprecated APIs,
and the final paired startup benchmark is 27% faster. These results help the
dotfiles owner assess the changes; they measure Neovim work, not Ghostty's GPU
presentation. Raw results are in [the benchmark data](nvim-2026-10-12.json).

## Commit editing and preserved behavior

A disposable repository with 290 staged files and about 154,000 added lines
reproduced a 7.3-second stall building and displaying Neogit's automatic staged
preview. Writing the commit message took about 10 ms. The owner approved
disabling that preview; manual Diffview remains available. The editor then
entered insert mode, accepted a message, and returned to status after aborting.
The tests did not commit or modify the owner's repository index.

Comparison snapshots retain all 1,984 icons, completion sources, ordinary
statusline output, 179 user commands, and Git Conflict autocommands. Notification
history and dismissal now use the existing nvim-notify provider. The large-file
Treesitter guard stops highlighters already started by built-in filetype plugins.
Completion respects Snacks' existing large-file disable flag. Search counters
cache identical states and use the existing `?/?` display when a scan exceeds
the new 5 ms budget.

## Measurements

Startup medians: **453 ms → 329 ms**, ten samples per configuration, alternating
order, with warm caches and patch signatures cached. An earlier paired run was
360 ms → 246 ms; absolute timings vary with machine activity.

The attached Neovim UI used 200 columns, 55 rows, and `ext_linegrid`. Each workload
had 80 samples for full redraw, cursor movement, half-page scrolling, and typing.
Input measurements include RPC transport and Python decoding through a scheduled
redraw notification. Completion can finish asynchronously afterward. External
LSP clients, Copilot, and tool installation were excluded from timing runs.

| Workload | Scroll p95, before → after | Typing p95, before → after |
| --- | --- | --- |
| 1,500 Lua lines | 12.7 → 9.5 ms | 13.1 → 15.5 ms |
| 1,500 lines, 2,000 diagnostics | 16.1 → 7.3 ms | 26.3 → 19.2 ms |
| 3,000 Lua lines | 14.8 → 4.8 ms | 17.8 → 3.3 ms |
| 30,000 Lua lines | 5.4 → 4.6 ms | 16.1 → 0.8 ms |
| 30,000 lines with active search | 34.5 → 10.1 ms | 88.2 → 9.2 ms |

Full-redraw p95 stayed below 8 ms in the final configuration. The animated
statusline remained active at approximately ten updates per second. A separate
1,000-call statusline test with 2,000 diagnostics took 1,327 ms before and 72 ms
after; that measures string generation only.

Ordinary typing was slightly slower in this particular comparison, and the
diagnostic stress case still reached 30 ms. The results show improvements in
the expensive paths, not a guarantee that every input fits a 16.7 ms frame.

## Health and regression checks

The final attached-UI health run used the configured LSP definitions and network
access for provider checks. `vim.deprecated` reported no deprecated functions,
including after file-browser and Diffview use. Git Conflict validation, Python
formatting, and the Python provider used by Visual Multi passed. Plugin lockfile
revisions now match installed versions without changing those versions.

Remaining health errors concern missing optional Ghostscript/PDF and TeX tools,
and graphics support unavailable in the RPC test UI. Optional warnings include
autopep8, shfmt, jsregexp, Node/Ruby remote providers, Mercurial, and parsers for
some document formats. Project-local formatter conditions and intentionally
disabled modules also produce informational warnings. These were not hidden or
resolved by installing unrelated packages.

Run the retained regression checks from the repository root:

```sh
nvim --headless -u NONE -i NONE -n -l nvim/tests/performance.lua
nvim --headless -u NONE -i NONE -n -l nvim/tests/plugin_patches.lua
```

StyLua and scoped whitespace checks passed. The disposable RPC harness and full
health report are retained under `/private/tmp/nvim-perf-onqpfyzu` for this
session. Ghostty GPU rendering, font rasterization, and live LSP/Copilot latency
were not measured. Restart Neovim to replace modules already loaded in memory,
then run `:checkhealth vim.deprecated`.
